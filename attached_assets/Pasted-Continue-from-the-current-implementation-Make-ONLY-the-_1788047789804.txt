1. REMOVE OBSOLETE QUALIFICATION FRAMEWORK FROM ACTIVE LOGIC

The latest audit confirmed that these legacy concepts still exist in executable code:

* Watchlist
* Near-Miss
* PASS
* Rejected
* S/A/B/C tiers

They must no longer influence the current monitoring, evaluation, qualification, or delivery framework.

Current rule

The active model is:

Monitor → Evaluate → Direction → Evidence → Safety checks → Delivery

A current prop is actionable only when it has:

* Valid OVER or UNDER direction
* Legitimate supporting evidence
* Valid provider/current line
* Valid pregame/event timing
* Existing deduplication/flood/safety protections

Nothing else should act as a qualification gate.
