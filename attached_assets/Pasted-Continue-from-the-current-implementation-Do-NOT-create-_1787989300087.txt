ACTIVE PROP RESCANNING — FINAL MONITORING CORRECTION

Fix the active player-prop monitoring lifecycle so that every currently active, supported non-football prop remains eligible for continuous rescanning until its event starts or the provider removes it.

The purpose is to ensure the bot does not miss opportunities simply because a prop:

* did not move
* was already evaluated
* was previously rejected
* was previously delivered
* is a stable line
* has weak evidence
* is cold-start
* is not currently directional

1. AUTHORITATIVE ACTIVE UNIVERSE

The active monitoring universe must come from the latest active provider/source-ID state.

For Underdog:

* latest active Underdog source IDs
* current active state
* event/game timing
* removal state
* alternate active lines where applicable

For PrizePicks:

* latest active PropLine source IDs
* current active state
* event/game timing
* removal state
* alternate lines where applicable

Historical snapshot rows must remain historical records.

Do NOT use historical snapshot count as the active monitoring universe.

Do NOT use only candidate records.

Do NOT use only line movers.

Do NOT use only new props.

Do NOT use only previously actionable props.

2. FPR MUST BE THE SOLE FULL-POOL ROTATION

Keep FPR as the only full-pool rotation mechanism.

Required lifecycle:

ACTIVE SOURCE-ID UNIVERSE
→ bounded FPR batch
→ evaluate/rescore
→ persist observation
→ advance cursor
→ next batch
→ continue
→ wrap
→ next rotation

Do NOT create another full-pool cursor.

Do NOT create another competing background rotation.

Stable Refresh has already been removed as an independent background job. Keep it that way.

3. EVERY ACTIVE PROP MUST ROTATE

Every active supported prop must eventually be rescanned.

This includes:

* unchanged props
* previously scored props
* previously rejected props
* previously delivered props
* non-actionable props
* cold-start props
* props with missing evidence
* props with no previous line movement

A prop remaining unchanged does NOT mean it can be permanently skipped.

1. Newly discovered props
2. Line movers
3. Urgent movement/actionable changes
4. Remaining active props requiring coverage
5. Previously scanned stable props

However, priority must NOT cause starvation.

The remaining active universe must continue advancing toward complete coverage.

After the cursor reaches the end, start another rotation.

* enter the active universe

* be evaluated

* return in future FPR rotations
