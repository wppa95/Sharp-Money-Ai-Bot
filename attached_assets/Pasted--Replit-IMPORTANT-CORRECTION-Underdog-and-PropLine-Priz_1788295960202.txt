IMPORTANT CORRECTION:

Underdog and PropLine/PrizePicks are supposed to run on the SAME MONITORING CADENCE in V4.

This is not only a reporting issue.

The actual runtime behavior must be:

ONE SHARED MONITORING CYCLE
├── Underdog
└── PropLine/PrizePicks

Both provider branches should be triggered as part of the same scheduled monitoring cycle and should repeat on the same cadence.

If the configured monitoring cadence is 5 minutes, both should participate in every 5-minute monitoring cycle.

Do NOT allow this situation:

Underdog → completes
Underdog → starts next cycle
PropLine → still processing an older cycle

That creates two independent monitoring rhythms, which is NOT the V4 design.

## REQUIRED BEHAVIOR

At each monitoring-cycle trigger:

1. Start the shared monitoring cycle.
2. Run Underdog monitoring.
3. Run PropLine/PrizePicks companion processing.
4. They may execute concurrently/parallel where appropriate.
5. Wait for both required branches to finish.
6. Mark the shared cycle complete.
7. The next shared cycle begins on the same cadence.

The providers do NOT need to execute sequentially.

They DO need to be triggered by the same shared cadence.

Example:

12:00 → UD + PP
12:05 → UD + PP
12:10 → UD + PP
12:15 → UD + PP

Not:

12:00 → UD
12:02 → PP
12:05 → UD
12:07 → PP

And not:

12:00 → UD
12:05 → UD
12:10 → UD
12:12 → PP
