==================================================
REMOTE DIAGNOSIS + RECOVERY GOAL
==================================================

The goal is not only to identify the problem.

The goal is to diagnose and solve problems without needing to open Replit.

The bot should provide enough information through Telegram to determine:

- Is the bot running?
- Did it restart?
- Did a scheduler fail?
- Did a provider fail?
- Did Telegram disconnect?
- Did the environment stop the process?

Add safe recovery:

- automatic reconnects
- scheduler recovery
- provider retry handling
- error recovery
- health restoration

The user should only need Replit for code changes, not normal monitoring.

==================================================
NO SILENT FAILURES RULE
==================================================

Any background job, scheduler, provider, database process, or Telegram process failure must never fail silently.

Any failure must:

- create a log entry
- update system health status
- expose the issue through Telegram monitoring
- attempt recovery if safe

The bot should never appear healthy while a critical component is failing.

Health status must reflect:

- provider failures
- scheduler failures
- Telegram failures
- database failures
- crashed jobs
- stopped workers

3. UNDERDOG PROP REMOVAL ALERT FIX
==================================================

Current issue:

Removal alerts are being sent for props the user never knew existed.

Fix lifecycle rules.

Only send removal alerts if:

1. The prop was previously tracked.
2. The prop reached ACTIVE ALERTED status.
3. The user previously received a notification.

Do not alert removals for:

- cold-start props
- silent database discoveries
- backfills
- internal-only records

- first_seen
- first_alert_sent_time
- last_seen
- last_alert_time
- activation_status
- removal_status
