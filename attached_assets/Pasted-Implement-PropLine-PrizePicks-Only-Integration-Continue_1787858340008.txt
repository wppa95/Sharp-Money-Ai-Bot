Implement PropLine → PrizePicks-Only Integration

Continue from the current Sharp Money Bot implementation.

The PROPLINE_API_KEY secret is already configured in Replit and Railway.

Make ONLY the targeted changes required below.

Goal

Add PropLine as a PrizePicks-only current-line provider so the bot can use PrizePicks alongside the existing Underdog monitoring system.

Requirements

1. PropLine Scope

Use PropLine ONLY for PrizePicks player props.

Do NOT use PropLine for:

* Underdog
* DraftKings
* FanDuel
* Moneylines
* Game totals
* Any other sportsbook
* Any other monitoring purpose

Existing Underdog, DraftKings/FanDuel, and OddsAPI integrations remain unchanged.

2. API Authentication

Read the existing environment variable:

PROPLINE_API_KEY

Never hard-code the API key.

If the key is missing, the provider must gracefully disable itself without crashing the bot.

3. Shared Prop Model

Normalize PropLine PrizePicks data into the bot’s existing player-prop representation.

Preserve:

* Provider/source = PrizePicks
* Player identity
* Sport
* Event/game
* Market/stat
* Line
* Over/Under direction where available
* Source/external ID where available
* Provider timestamp/freshness information

Do not create a second incompatible prop model.

4. PrizePicks Confirmation

Use PropLine PrizePicks data as an additional confirmation/reference source for the existing Underdog player-prop pipeline.

When an Underdog player prop has a matching PrizePicks prop, conservatively compare:

* Player
* Sport
* Event/game
* Market/stat
* Line
* Direction
* Freshness
* Source identity

Reject ambiguous or stale matches.

Do not fabricate a match when identity cannot be established confidently.

Do NOT re-enable the existing direct PrizePicks API client.

Do NOT attempt to bypass DataDome.

Do NOT use browser automation, proxy rotation, CAPTCHA solving, fingerprint spoofing, or any other anti-bot circumvention.
