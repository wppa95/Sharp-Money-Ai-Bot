FIX ACTIONABLE ALERT SPAM / MEANINGFUL OPPORTUNITY DEDUPLICATION

The monitoring system must continue rescanning every active prop, but Telegram delivery must NOT repeatedly alert on the same unchanged opportunity.

These are separate concerns:

MONITORING = continuous rescanning of the full active universe.

DELIVERY = only notify when there is a meaningful new actionable opportunity.

1. CORE REQUIREMENT

Repeated rescans of the same unchanged prop must NOT generate repeated Telegram alerts.

Example:

Max Muncy — Batter Strikeouts — UNDER 1.5

If the bot rescans the same:

* provider
* source ID
* event
* player
* market/stat
* line
* direction
* actionable state

it should NOT send another identical alert.

The prop must continue being monitored and rescored internally.

Only the duplicate delivery should be suppressed.

2. MEANINGFUL CHANGES MUST BE ALLOWED

A meaningful opportunity change should create a new delivery opportunity.

Examples:

* 0.5 → 1.5 line movement
* 1.5 → 2.5 line movement
* UNDER → OVER
* OVER → UNDER
* different provider
* different source ID
* different event
* materially changed actionable state

These should be treated as distinct opportunities when the existing identity model indicates they are distinct.

Do NOT suppress legitimate new opportunities merely because the player and market are the same.

3. PROVIDER SEPARATION

The deduplication identity must remain provider-aware.

Underdog and PrizePicks must never suppress each other’s alerts.

For example:

🐶 Underdog — Player X — Points 20.5 — OVER

and

🟣 PrizePicks — Player X — Points 20.5 — OVER

are separate delivery opportunities.

Provider must remain part of the identity.

4. SOURCE-ID / EVENT-ID IDENTITY

Use the existing provider/source/event identity model.

Where available, delivery identity should distinguish:

* provider
* source ID
* event ID
* player
* sport
* market/stat
* line
* direction

Do NOT revert to player + market alone.

Do NOT create a second incompatible identity system.

5. RESCAN BEHAVIOR

A repeated rescan must:

* evaluate the prop
* update/persist tracking
* update evidence/history where applicable
* update grading state
* update current state

But it must NOT automatically create another Telegram delivery.

This remains true even if:

* the prop is rescanned 10 times
* the prop is rescanned 50 times
* the prop is rescanned 100 times

One unchanged actionable opportunity should produce one delivery opportunity.

6. LINE MOVEMENT

When a line changes, the new line must be eligible for a new alert.

Example:

Initial:

🐶 UNDERDOG
Max Muncy
Batter Strikeouts 0.5
UNDER

Later:

🐶 UNDERDOG
Max Muncy
Batter Strikeouts 1.5
UNDER

The second state must be eligible for delivery because the opportunity materially changed.

Do not let the old dedup claim permanently suppress the new line.

7. DIRECTION CHANGES

If:

UNDER → OVER

or:

OVER → UNDER

the changed directional opportunity must be eligible for delivery.

The previous direction must not permanently suppress the new direction.

8. FAILED DELIVERY / CLAIM RETENTION

Preserve the existing atomic delivery-claim behavior.

Claims may be acquired before sending to prevent concurrent duplicates.

If delivery is:

* filtered
* rate-limited
* rejected
* otherwise unsuccessful

the claim must be released so the opportunity can be retried.

Only successful delivery should create durable suppression.

Do NOT regress the existing failed-delivery claim-release fix.
