🔥 PRIORITY FIX — ROLLING STABLE-PROP RESCANNING + WATCHLIST RESCANNING + VISIBLE SCAN PROGRESS

We need to implement the stable-prop refresh we discussed.

🎯 MAIN OBJECTIVE

The bot currently has a huge active Underdog pool, but it primarily scores:

* New first-appearance props
* Line-moved props
* Cold-start props

That means thousands/millions of stable props can sit there without being rescored, even if they are actually strong betting lines.

We need continuous coverage of the stable pool AND continuous monitoring of the watchlist.

⸻

🔄 1. STABLE REFRESH SYSTEM

Keep the existing fast/incremental pipeline exactly as-is.

Add a separate rolling stable-refresh process.

Every 2 minutes:

1. Take the next 10,000 stable/unchanged active props
2. Re-score those 10,000
3. Run them through the existing scoring + qualification + direction + BQ + confidence + dedup + live-game gates
4. Send legitimate qualifying alerts through the normal Telegram path
5. Record/update watchlist candidates
6. Advance the cursor to the next 10,000
7. Repeat every 2 minutes

DO NOT:

* Brute-force the entire active pool every 2 minutes
* Re-fetch the entire pool just to accomplish this
* Create a second scoring model
* Bypass existing alert gates
* Re-alert the same prop repeatedly
* Let stable refresh interfere with new/line-moved processing

⸻

📍 2. PERSISTENT ROLLING CURSOR

The stable refresh needs a persistent cursor.

Example:

Batch 1:       0 → 10,000
Batch 2:  10,000 → 20,000
Batch 3:  20,000 → 30,000
...

The cursor should continue across refreshes and preferably survive restarts so the bot doesn’t continually rescore the same first 10k.

When it reaches the end of the stable pool, wrap around and start a new rotation.

If props become line-moved/new/removed while waiting in the stable queue, handle them through the appropriate normal pipeline and prevent duplicate processing.

⸻

👁️ 3. WATCHLIST RE-SCANNING

Watchlist candidates must NOT be passive records that sit there until a line movement occurs.

Every active watchlist candidate should also be continuously re-evaluated.

Every 2 minutes:

* Re-score active watchlist candidates
* Re-check current line
* Re-check scoring dimensions
* Re-check direction
* Re-check BQ
* Re-check confidence
* Re-check tier
* Re-check qualification status

If a watchlist candidate improves enough to qualify:

IMPORTANT:

Use the existing scoring engine.

Do NOT create a separate watchlist scoring system.

10,000 props / 2 minutes
