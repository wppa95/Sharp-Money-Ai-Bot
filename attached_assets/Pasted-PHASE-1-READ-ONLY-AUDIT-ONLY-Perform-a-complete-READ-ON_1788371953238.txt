PHASE 1 — READ-ONLY AUDIT ONLY

Perform a complete READ-ONLY inspection of the current Sharp Money Bot before implementing Phase 1.

Do NOT make any code changes.
Do NOT deploy.

The purpose is to establish exactly what is already implemented so Phase 1 can be applied without duplicating or breaking existing functionality.

1. Provider Architecture

Inspect and document exactly how player-prop data currently enters the bot.

Specifically determine:

* Whether Underdog currently has its own direct/source connector.
* Whether PrizePicks currently has its own direct/source connector.
* Whether PropLine is used as an underlying/alternate data source.
* Whether Underdog uses its own source first and falls back to PropLine when available.
* Whether PrizePicks uses PropLine.
* The exact provider/source priority and fallback behavior.
* Which provider/source is authoritative when both are available.
* Whether provider identity is preserved after normalization.
* Whether any third sportsbook/provider is currently being used.

Do not change this behavior during the audit.

2. PropLine Integration

Inspect:

* PropLine client/request path.
* All PropLine endpoints currently used.
* Centralized request limiter.
* Current hard hourly limit.
* Current request spacing.
* 429/Retry-After handling.
* Missing-key behavior.
* Whether every PropLine request passes through the centralized limiter.
* Whether any bypass path exists.

Verify the recently implemented 208/hour / ~17.3-second cadence is actually present.

3. Underdog Source

Inspect the complete Underdog ingestion path.

Determine:

* Direct Underdog source/connector.
* PropLine fallback, if present.
* How source selection works.
* What happens when direct Underdog data is unavailable.
* What happens when PropLine data is unavailable.
* Whether duplicate data from multiple sources is deduplicated correctly.
* Stable provider/player/prop identity handling.
* Current line snapshot behavior.

4. Scheduler & Monitoring

Determine:

* Monitoring interval.

* Monitoring coordinator.
* Overlap protection.
* Whether framework max_instances exists anywhere.

* Whether stopped runs can remain alive/wait for completion.
* Restart/session-state behavior.
* Whether the system starts a clean runtime session after restart.
