1. CRITICAL REQUIREMENT: SCAN ALL SPORTS, ALL MARKETS, ALL PLAYERS, AND ALL AVAILABLE LINES

V4 must inspect every supported sport and every player-prop market and line that the existing data sources actually expose.

The bot must not scan only the markets that currently produce alerts, the markets its grading system prefers, or the props it predicts are most likely to qualify.

Discovery must be comprehensive. Alert delivery can remain selective.

For every supported sport and active event:

- Discover all available player props.
- Discover every available stat and market type.
- Discover every player with an available prop.
- Inspect every distinct offered line for each player and stat.
- Identify which platform provides each offering.
- Record actual available directions when the source exposes that information.
- Preserve standard lines and special lines, including PrizePicks Goblins and Demons where applicable.
- Support previously unseen market identifiers and aliases through safe, extensible normalization.
- Continue scanning all supported sports, not only MLB, NHL, NBA, NFL, or any other predefined shortlist.
- Include supported esports, tennis, and other sports already handled by V4.
- Do not stop scanning an event after finding a few potentially profitable props.
- Do not use grading rank, historical alert frequency, or qualification status to decide which markets are discovered.

If a source exposes multiple lines for the same player and stat, evaluate each distinct offering independently when sufficient data is available.

Do not invent lines, assume that both OVER and UNDER are available, or assume that a market exists on a platform without evidence from that platform's data.

If a source does not expose a market or line, record that limitation rather than pretending the market was scanned successfully.

2. SEPARATE MARKET DISCOVERY FROM PICK SELECTION

Keep these responsibilities separate:

1. Discovery: Find all available offerings across supported sports and sources.
2. Normalization: Map raw provider data to consistent sport, event, player, stat, platform, line, direction, and market-type fields.
3. Storage: Persist observations so they can be tracked and evaluated.
4. Evaluation eligibility: Determine which offerings have the minimum required data for evaluation.
5. Evaluation: Evaluate each eligible offering independently.
6. Evidence and history: Gather valid historical results, hit rates, and other existing evidence.
7. Analysis and qualification: Apply V4's existing grading, evidence, and qualification requirements.
8. Alert creation: Create alerts only for genuinely qualified opportunities.
9. Delivery: Send qualified individual picks through Telegram.

An offering must not be excluded from discovery simply because it is unlikely to qualify.

A weak prop may fail qualification, but V4 should still be able to show that it was observed and explain why it was rejected.

Do not lower grading thresholds, weaken evidence requirements, or manufacture additional picks to make the bot appear more active.

4. FIX CROSS-PLATFORM LINE COMPARISON

V4 must compare equivalent offerings from PrizePicks and Underdog when the existing sources provide sufficient data.

For each comparison, verify:

- Same player.
- Same event.
- Same statistical market.
- Same statistical definition and settlement rules.
- Actual line on each platform.
- Actual platform identity.
- Actual direction availability.
- Regular line versus special line classification.
- Whether the comparison is current and sufficiently complete.

Do not compare unrelated markets merely because their labels appear similar.

Platform-specific availability is mandatory

PrizePicks and Underdog must be treated as separate platforms with independent line and direction availability.

For example, if PrizePicks offers a player at 0.5 home runs but Underdog does not offer an UNDER selection for that market, V4 must not recommend an Underdog UNDER as if it were playable.

Likewise, do not assume that a line visible on Underdog exists on PrizePicks.

Do not automatically reverse the recommended direction to force a comparison. If the recommended direction is unavailable on the named platform, do not present it as a playable pick there.

If only one platform has a confirmed offering, V4 may still evaluate that offering independently. Missing comparison data must not automatically disqualify an otherwise valid pick.

Correct line-difference calculations

Calculate the absolute difference between verified equivalent lines:

"line_difference = abs(platform_a_line - platform_b_line)"

Display the actual difference accurately.

Explain directional value separately. For equivalent markets, a lower line may favor the OVER and a higher line may favor the UNDER, but the correct interpretation depends on the exact stat, direction, settlement rules, and available offerings.

Do not claim that a line difference alone proves a profitable edge.

Fixed payouts, odds, and special lines

Preserve the distinction between:

- PrizePicks fixed-payout offerings.
- Underdog fixed-payout offerings.
- Available odds-based offerings, if exposed by an existing source.
- PrizePicks Goblin and Demon lines.
- Standard lines and other special offerings.

Do not compare a special line with a standard line as if they were identical. Explicitly label the classification and explain the difference.

Only display odds, payout details, or line classifications when supported by actual source data. Do not invent odds or imply that a source provides them when it does not.

6. REQUIRED HISTORICAL WINDOWS: L5, L10, L20, L30, H2H

Preserve and implement the five requested history windows:

- L5 — last 5 valid games.
- L10 — last 10 valid games.
- L20 — last 20 valid games.
- L30 — last 30 valid games.
- H2H — valid head-to-head games against the current opponent.

Do not substitute L15 or season-to-date results for these requested windows. Do not silently omit a window simply because another window already exists.

For each window, display the actual result sequence when the existing data supports it, the percentage for the recommended direction, and the correct numerator and denominator.

For example:

L5 (UNDER): 0, 0, 0, 0, 1 · 80% (4/5)

For a 0.5 line, assuming the displayed numbers are the player's actual counts, four zero results would be UNDER hits. They would not be OVER hits.

Historical calculation requirements

- Calculate hit rates against the exact offered line and recommended direction.
- Respect the market's actual settlement rules.
- Use completed, valid games only.
- Exclude DNPs, missing results, and invalid records from the denominator.
- Handle pushes and special settlement cases according to the market's rules; do not automatically count them as hits.
- Keep chronological ordering consistent and documented.
- Ensure L5 is based on the five most recent valid games, L10 on the ten most recent, and so forth.
- Compute H2H using the actual opponent and valid prior meetings.
- Display N/A when there is insufficient valid history.
- Never fabricate results or treat missing history as zero.
- Never label a player's raw scoring frequency as the hit rate for the recommended direction unless the two genuinely match.

When a window has fewer valid games than requested, display the actual sample size and do not imply that a complete sample exists.

If the current history source cannot support a requested window, record that limitation and investigate whether the existing sources already provide the missing data. Do not add a paid data provider.
