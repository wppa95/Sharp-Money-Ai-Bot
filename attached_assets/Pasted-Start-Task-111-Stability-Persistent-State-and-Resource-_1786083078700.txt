1. Fix SIGKILL / OOM Memory Growth

Current finding:

Multiple unexpected exits show:

* shutdown_at = null
* session_secs = null
* last_crash_detail = null

This indicates host-level termination (SIGKILL/OOM), not a Python exception.

Observed:

* Memory RSS grows approximately 50 MB per Underdog scan cycle.
* Bot is being killed every 10–20 minutes.

Investigate:

* Underdog scan memory growth
* Objects accumulating between scans
* In-memory lists/caches growing without limits
* Duplicate stored objects
* Unreleased scan results
* Background job memory retention

Fix:

* Add cleanup where needed
* Add limits to temporary memory structures
* Prevent unbounded growth
* Keep database as the source of truth

Do not solve this by disabling the pipeline.
